## Introduction

Programming is the bridge between your ideas and a working robot. While mathematics describes what we want robots to do, programming makes it happen. In the world of Physical AI, Python has become the dominant language for its readability, extensive libraries, and strong support in both AI/ML and robotics communities.

This chapter introduces the programming skills you need to start building robotic systems. We will cover Python basics (if you're new to programming), the essential ROS2 concepts that form the backbone of modern robot software, and practical skills for setting up your development environment.

Do not worry if you have never programmed before. We will start from the basics and build up to writing code that controls robots. The key is practice—every roboticist started by writing their first line of code.

### Section 1: Why Python for Robotics?

Python has become the language of choice for robotics and AI for several reasons:

**Readability**: Python code looks almost like English, making it easier to learn and understand.

**Libraries**: NumPy for math, OpenCV for vision, PyTorch/TensorFlow for AI—Python has everything you need.

**ROS2 Support**: ROS2 provides excellent Python bindings (rclpy).

**Rapid Prototyping**: Quick iteration lets you test ideas fast.

**Community**: Massive community means help is always available.

:::note Key Concept
While Python is great for high-level control and AI, performance-critical robot code (like real-time motor control) often uses C++. Many robots use both languages together.
:::

### Section 4: Introduction to ROS2

ROS2 (Robot Operating System 2) is a framework for building robot software. It provides:
- Communication between processes (nodes)
- Hardware abstraction
- Tools for visualization and debugging
- A large ecosystem of packages

**Core Concepts**:

**Nodes**: Independent processes that perform specific functions.
```
[Camera Node] → processes images
[Motor Node] → controls motors
[Navigation Node] → plans paths
```

**Topics**: Named channels for streaming data.
```
/camera/image → image data flows here
/cmd_vel → velocity commands flow here
/odom → odometry data flows here
```

**Messages**: Structured data sent over topics.
```python
# Example: geometry_msgs/Twist for velocity
twist = Twist()
twist.linear.x = 0.5   # forward speed
twist.angular.z = 0.1  # rotation speed
```

**Publishers and Subscribers**:
- Publishers send messages to topics
- Subscribers receive messages from topics
- Many-to-many relationships are possible

### Section 5: Writing Your First ROS2 Node

Here's a simple ROS2 node structure:

```python
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist

class SimpleController(Node):
    def __init__(self):
        super().__init__('simple_controller')

        # Create a publisher
        self.publisher = self.create_publisher(
            Twist,          # Message type
            '/cmd_vel',     # Topic name
            10              # Queue size
        )

        # Create a timer to publish periodically
        self.timer = self.create_timer(
            0.1,            # Period in seconds
            self.timer_callback
        )

        self.get_logger().info('Simple controller started!')

    def timer_callback(self):
        msg = Twist()
        msg.linear.x = 0.2  # Move forward
        msg.angular.z = 0.0 # No rotation
        self.publisher.publish(msg)

def main(args=None):
    rclpy.init(args=args)
    node = SimpleController()
    rclpy.spin(node)
    node.destroy_node()
    rclpy.shutdown()

if __name__ == '__main__':
    main()
```

### Section 7: Debugging Robotics Code

Common issues and solutions:

**Import Errors**:
```python
# Wrong
import ros2  # This doesn't work!

# Right
import rclpy
from rclpy.node import Node
```

**Topic Name Mismatches**:
```bash
# Use ros2 topic list to see available topics
ros2 topic list

# Check for typos in topic names
```

**Timing Issues**:
```python
# Bad: blocking call
while not condition:
    pass  # This blocks everything!

# Good: use ROS2 timers and callbacks
self.timer = self.create_timer(0.1, self.check_condition)
```

**Coordinate Frame Confusion**:
- Always be explicit about which frame your data is in
- Use TF2 for transformations between frames

```python
# Part 2: Functions for Robot Operations

import math

def normalize_angle(angle):
    """Normalize angle to [-pi, pi]"""
    while angle > math.pi:
        angle -= 2 * math.pi
    while angle < -math.pi:
        angle += 2 * math.pi
    return angle

def calculate_heading(x1, y1, x2, y2):
    """Calculate heading angle from point 1 to point 2"""
    dx = x2 - x1
    dy = y2 - y1
    return math.atan2(dy, dx)

def distance_to_goal(current_x, current_y, goal_x, goal_y):
    """Calculate Euclidean distance to goal"""
    return math.sqrt((goal_x - current_x)**2 + (goal_y - current_y)**2)

# Test the functions
current_pos = (0, 0)
goal_pos = (3, 4)

heading = calculate_heading(*current_pos, *goal_pos)
dist = distance_to_goal(*current_pos, *goal_pos)

print("=== Part 2: Navigation Functions ===\n")
print(f"Current position: {current_pos}")
print(f"Goal position: {goal_pos}")
print(f"Heading to goal: {math.degrees(heading):.1f} degrees")
print(f"Distance to goal: {dist:.2f} meters")
```

```python
# Part 3: Classes for Robot Representation

class DifferentialDriveRobot:
    """A simple differential drive robot model"""

    def __init__(self, name, wheel_radius=0.1, wheel_base=0.5):
        self.name = name
        self.wheel_radius = wheel_radius
        self.wheel_base = wheel_base

        # State
        self.x = 0.0
        self.y = 0.0
        self.theta = 0.0

    def set_wheel_speeds(self, left_speed, right_speed, dt):
        """
        Update robot position based on wheel speeds.
        Speeds are in rad/s, dt is time step in seconds.
        """
        # Convert wheel speeds to linear velocities
        v_left = left_speed * self.wheel_radius
        v_right = right_speed * self.wheel_radius

        # Calculate robot velocities
        v = (v_right + v_left) / 2.0
        omega = (v_right - v_left) / self.wheel_base

        # Update position (simple Euler integration)
        self.x += v * math.cos(self.theta) * dt
        self.y += v * math.sin(self.theta) * dt
        self.theta = normalize_angle(self.theta + omega * dt)

    def get_position(self):
        return (self.x, self.y, self.theta)

    def __str__(self):
        return f"{self.name} at ({self.x:.2f}, {self.y:.2f}, θ={math.degrees(self.theta):.1f}°)"

# Test the robot class
print("=== Part 3: Robot Class ===\n")
robot = DifferentialDriveRobot("TestBot")
print(f"Initial: {robot}")

# Move forward
for _ in range(10):
    robot.set_wheel_speeds(5.0, 5.0, 0.1)  # Equal wheel speeds = straight
print(f"After moving forward: {robot}")

# Turn
for _ in range(10):
    robot.set_wheel_speeds(5.0, 2.0, 0.1)  # Different speeds = turn
print(f"After turning: {robot}")
```

```python
# Part 5: Simple Go-to-Goal Controller

class GoToGoalController:
    """Proportional controller to drive robot to goal"""

    def __init__(self, k_linear=0.5, k_angular=2.0):
        self.k_linear = k_linear    # Linear gain
        self.k_angular = k_angular  # Angular gain

    def compute_control(self, robot, goal_x, goal_y):
        """Compute wheel speeds to move toward goal"""
        # Calculate error
        dx = goal_x - robot.x
        dy = goal_y - robot.y

        # Distance and angle to goal
        distance = math.sqrt(dx**2 + dy**2)
        angle_to_goal = math.atan2(dy, dx)

        # Angle error (normalized)
        angle_error = normalize_angle(angle_to_goal - robot.theta)

        # Proportional control
        v = self.k_linear * distance
        omega = self.k_angular * angle_error

        # Convert to wheel speeds
        v_left = (v - omega * robot.wheel_base / 2) / robot.wheel_radius
        v_right = (v + omega * robot.wheel_base / 2) / robot.wheel_radius

        return v_left, v_right, distance

print("=== Part 5: Go-to-Goal Controller ===\n")

# Create robot and controller
robot = DifferentialDriveRobot("NavBot")
controller = GoToGoalController()

# Define goal
goal = (3.0, 4.0)
print(f"Goal: {goal}")
print(f"Initial: {robot}")

# Track path
path_x = [robot.x]
path_y = [robot.y]

# Control loop
dt = 0.05
max_iterations = 1000
goal_tolerance = 0.1

for i in range(max_iterations):
    left_speed, right_speed, distance = controller.compute_control(robot, *goal)

    if distance < goal_tolerance:
        print(f"\nGoal reached in {i} iterations!")
        break

    robot.set_wheel_speeds(left_speed, right_speed, dt)
    path_x.append(robot.x)
    path_y.append(robot.y)

print(f"Final: {robot}")

# Plot
plt.figure(figsize=(10, 10))
plt.plot(path_x, path_y, 'b-', linewidth=2, label='Robot path')
plt.plot(path_x[0], path_y[0], 'go', markersize=15, label='Start')
plt.plot(*goal, 'r*', markersize=20, label='Goal')

plt.xlabel('X (meters)')
plt.ylabel('Y (meters)')
plt.title('Go-to-Goal Navigation')
plt.legend()
plt.grid(True)
plt.axis('equal')
plt.show()
```

3. **Create a publisher node** (`my_first_package/my_first_package/simple_publisher.py`):
```python
#!/usr/bin/env python3
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist

class SimplePublisher(Node):
    def __init__(self):
        super().__init__('simple_publisher')
        self.publisher = self.create_publisher(Twist, '/turtle1/cmd_vel', 10)
        self.timer = self.create_timer(0.5, self.timer_callback)
        self.counter = 0
        self.get_logger().info('Publisher started!')

    def timer_callback(self):
        msg = Twist()

        # Alternate between moving and turning
        if self.counter % 2 == 0:
            msg.linear.x = 1.0
            msg.angular.z = 0.0
            self.get_logger().info('Moving forward')
        else:
            msg.linear.x = 0.0
            msg.angular.z = 0.5
            self.get_logger().info('Turning')

        self.publisher.publish(msg)
        self.counter += 1

def main(args=None):
    rclpy.init(args=args)
    node = SimplePublisher()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.shutdown()

if __name__ == '__main__':
    main()
```

4. **Create a subscriber node** (`my_first_package/my_first_package/simple_subscriber.py`):
```python
#!/usr/bin/env python3
import rclpy
from rclpy.node import Node
from turtlesim.msg import Pose

class SimpleSubscriber(Node):
    def __init__(self):
        super().__init__('simple_subscriber')
        self.subscription = self.create_subscription(
            Pose,
            '/turtle1/pose',
            self.pose_callback,
            10
        )
        self.get_logger().info('Subscriber started!')

    def pose_callback(self, msg):
        self.get_logger().info(
            f'Turtle at x={msg.x:.2f}, y={msg.y:.2f}, theta={msg.theta:.2f}'
        )

def main(args=None):
    rclpy.init(args=args)
    node = SimpleSubscriber()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.shutdown()

if __name__ == '__main__':
    main()
```

## Case Study: The ROS Ecosystem Impact

### Background

When Willow Garage released ROS (Robot Operating System) in 2007, it addressed a fundamental problem in robotics: every lab was reinventing the wheel. Teams spent years writing basic infrastructure before they could start their actual research. ROS changed this by providing reusable components and a common framework.

### Implementation

ROS succeeded through several key decisions:

**Open Source**: BSD license allowed academic and commercial use without restrictions.

**Modular Design**: Packages could be shared and combined independently.

**Language Agnostic**: Support for both C++ (performance) and Python (ease of use).

**Community Focus**: Built around sharing packages and documentation.

**ROS2 Evolution** (2015-present):
- Real-time support for safety-critical applications
- Security features for deployed systems
- Support for embedded systems and multiple robots
- DDS (Data Distribution Service) middleware

### Results

The impact has been enormous:
- Used by 70%+ of robot developers worldwide
- Thousands of packages available
- Major robot companies use ROS/ROS2 (including NASA, Amazon, Toyota)
- Standard in robotics education globally
- Enabled rapid advancement in mobile robots, manipulators, and humanoids

### Lessons Learned

1. **Shared infrastructure accelerates innovation**: Everyone benefits from common tools
2. **Community matters**: Active contributors and users drive improvement
3. **Documentation is crucial**: Clear docs lower the barrier to entry
4. **Evolution is necessary**: ROS2 addressed ROS1's limitations
5. **Standards enable collaboration**: Common interfaces let packages work together

### Question 2

In ROS2, what is a "topic"?

A) A conversation subject in the documentation
B) A named channel where data is published and subscribed
C) A type of robot
D) A programming function

<details>
<summary>Answer</summary>
**B**: A topic in ROS2 is a named channel for data communication. Nodes publish messages to topics, and other nodes subscribe to receive those messages.
</details>

### Question 3

What is the purpose of the `rclpy.spin()` function?

A) To make the robot rotate
B) To keep the node running and processing callbacks
C) To compile the code
D) To connect to the internet

<details>
<summary>Answer</summary>
**B**: The `rclpy.spin()` function keeps the node running and processes incoming callbacks (like timer and subscription callbacks) until the node is shut down.
</details>

### Question 4

What message type is typically used to send velocity commands in ROS2?

A) std_msgs/String
B) sensor_msgs/Image
C) geometry_msgs/Twist
D) nav_msgs/Odometry

<details>
<summary>Answer</summary>
**C**: `geometry_msgs/Twist` contains linear and angular velocity components, making it the standard message type for velocity commands (like `/cmd_vel` for mobile robots).
</details>

### Question 5

What is a common debugging approach when a ROS2 topic isn't working?

A) Reinstall the operating system
B) Use `ros2 topic list` and `ros2 topic echo` to check topic names and data

D) Ignore the problem

<details>
<summary>Answer</summary>
**B**: Using `ros2 topic list` shows all available topics (to check for typos), and `ros2 topic echo` shows the actual data being published, helping identify communication issues.
</details>
